# JiPaiQi Mobile

Android 本地记牌器。采用参考图的双行悬浮条：浅灰底、黑色牌点、橙色余量、灰色归零及黄色开关区。

## 安装与使用

首版面向 **Android 8.0+、ARM64** 手机，安装包在 `dist/JiPaiQi-Mobile-0.2.0-debug-arm64.apk`。这是开发测试签名版本，未发布到应用商店。

1. 安装并打开“记牌器”。已内置用户提供的 `jpq-config-20260909-001755.zip`（微乐跑得快、3 人、每人 16 张）。
2. 在发牌前点击“开始记牌”，通过系统界面允许悬浮窗和屏幕采集。Android 13+ 会请求通知权限。
3. 切换到横屏游戏。悬浮条默认贴右下角，宽度为屏幕的 35%；可在样式中调整到 25%–98%。左侧黄色开关暂停/继续；拖动悬浮条调整位置；点牌点区域或长按打开主页查看记录。
4. “样式与颜色”可设置六种颜色、宽度和透明度。“游戏画面范围”可校准黑边裁剪；未确认的布局比例不直接拉伸识别。
5. 在“出牌记录 / 待核对”中检查可疑候选。确实出牌可确认计入；结算剩余牌可忽略。支持撤销上一笔、手动确认新局、导出 JSON 记录。
6. 点击“停止识别”或通知中的“停止”，释放屏幕采集与悬浮窗。

余量定义为 **实际牌库减去各家已确认出牌**，包含我方尚未打出的手牌。此配置没有我方初始手牌识别区域，不宣称自动计算“仅对手持有”的牌。中途开启、暂停和系统打断不能补回漏过的出牌；应从下一局完整开始。

## 已实现

- ZIP 导入：先解压到私有临时目录，校验 manifest、路径、大小、图片、引用、牌库和必需算法；失败保留旧配置。
- 使用 Android MediaProjection + 前台服务截屏；OpenCV 在设备本地运行，手牌上传默认关闭、无 OCR、不自动操作游戏。
- 按有效画面等比映射回参考尺寸；灰度/彩色/Otsu 模板匹配与颜色新局检测。
- 移植 `cards.row_ownership.v1`：左右/我方区域竞争、最多 8 张换行、完整首行支持第二行。
- 连续确认、消失等待、结束优先及结束后锁定。新局要求开局特征消失再连续确认，避免残留手牌导致立即重置。
- 3 秒结算保护、候选 ID 去重、逐玩家张数和全牌库上限检查。入账为原子操作，不允许负数。
- 同牌组消失后再次出现，缺少回合证据时标记待核对，不能因为二次出现直接重复扣牌。
- 暂停、旋转、画面比例不符或悬浮窗遮挡识别区域时，停止自动入账并保留候选核对。
- 历史记录保存在应用私有目录，停止后可查看和导出；停止重启不悄悄恢复旧局计数。

## 构建

JDK 17、Android SDK platform 35 / build-tools 35.0.0；Gradle Wrapper 8.11.1、AGP 8.9.2、OpenCV 4.12.0。将本机 SDK 路径写入不提交的 `local.properties`，或配置 `ANDROID_HOME`。

```sh
./scripts/build.sh
./scripts/device-tests.sh 127.0.0.1:16384
```

设备端自动测试会安装独立的测试 APK，并展示由提供的视频提取的固定画面。真实截图链路测试需事先在系统界面允许本应用悬浮窗权限；屏幕采集仍通过系统确认弹窗授权。测试结束停止采集。没有该权限时此项测试会跳过，请检查测试摘要，不能把跳过当通过。

## 代码

- `Pack.java`：适配包验证与原子切换。
- `Vision.java`：OpenCV 检测、坐标转换、牌行归属。
- `Ledger.java`：纯 Java 状态机、候选与账本。
- `CaptureService.java`：屏幕采集、采样时钟、悬浮窗及会话保存。
- `CounterStrip.java` / `Appearance.java`：双行显示与样式持久化。
- `MainActivity.java`：权限、导入、设置与核对。

## 当前边界

已采集配置适用于对应游戏皮肤与布局；比例相近不保证不同设备上的游戏 UI 完全相同，仍需真机校准。完整牌型比较、回合身份与手牌数量识别不在当前配置中，因此可疑重复及临近结算记录采用人工核对，不猜牌。待核对期间余量可能偏大，不能当作已确认准确值。iOS、32 位 Android 未提供构建。

Android 14+ 前台服务/录屏授权按官方接口实现；已验证设备及测试结果见 `docs/verification.md`，不将一个模拟器的结果当作全部真机兼容性证明。

实现参考：[Android MediaProjection](https://developer.android.com/media/grow/media-projection)、[OpenCV Android](https://docs.opencv.org/4.13.0/d5/df8/tutorial_dev_with_OCV_on_Android.html)。

## v2 自己手牌（0.2.0）

新增独立的点数＋花色识别，不计作出牌，不扣减旧记牌账本。使用 jpq-tools 的 v2 分支，在“我方手牌”中采集全手牌区域和每种牌的点数＋小花色联合模板，导出并导入新配置包。原内置跑得快包只有出牌模板，不能识别新游戏的手牌。新包声明 `cards.hand_identity.v1`，旧客户端会拒绝而非丢失花色。

客户端“我方手牌 / 服务器上传”可查看当前结果并设置 HTTPS 接口。当前没有服务端地址，默认关闭上传；无接口也可本地识别。上传只包含点数、花色、数量及事件元数据，截图不落盘、不上传。接口鉴权尚待服务端协议确定，当前版本没有 Token 配置，不应对接要求鉴权的正式接口。

同一手牌连续确认后才生成快照；牌序调整不重复生成，相同花色点数的重复牌保留数量。空画面不当作零张手牌。配置了结束检测时，结束后锁定直到识别到下一局；只有手牌而无状态特征的配置不具备自动分局能力。暂停和采集恢复可能重新生成同一副手牌，服务器不能将快照当作新增出牌累加。

协议及重试边界见 [hand-upload-v2.md](docs/hand-upload-v2.md)。Android 的安全窗口（FLAG_SECURE）仍可能让采集结果为黑屏，本功能不能改变游戏的截屏保护。

v2 本地验证：46 项 Python 测试通过；15 项 Android JVM 单元测试通过，APK 编译通过。用户提供的单帧截图回归识别出 13 张含花色手牌（含两张梅花 5）。模板来自该参考图，这只验证匹配和重复牌处理，不代表未知画面准确率；v2 尚未做真机完整采集及服务端联调。原设备测试结论只适用于此前版本。
