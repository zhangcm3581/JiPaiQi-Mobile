# 十三水客户端 0.4.21 · v2

Android 两副牌手牌识别客户端：104 张，无大小王，每手 13 张。Android 8.0+、ARM64，开发测试签名。

0.4.21：只有点击启动才连接服务器；暂停立即关闭业务发送并断开WebSocket，停止心跳、重试和自动重连，面板隐藏并清空。恢复启动重新同步版本和可靠开局，不补传暂停前旧牌。详见 [暂停断网验证](docs/pause-network-0.4.21.md)。

0.4.20起取消上传前的 `round.join` 往返：两帧确认完整13张后直接提交，服务端在同一事务中登记本轮参与者并收牌。先更新配套服务端，再覆盖安装客户端。每租户最多20个登记ID，每轮任意7个不同ID参与，支持局间轮换。

## 使用

1. 安装 `dist/JiPaiQi-Mobile-0.4.21-debug-arm64.apk`。升级保留两个 ID，未经修改的内置旧素材包自动更新；应用不再显示主面板。
2. 打开应用，完成系统悬浮窗和屏幕采集授权后直接返回原画面，悬浮控制栏默认展开。已经运行时再次打开应用会展开原控制栏，不重复创建采集服务。安装本身不会绕过 Android 限制自动运行。
3. 点悬浮栏“设置”，在控制栏展开的设置区填写租户 ID 和客户端 ID。设置与控制栏视觉连成一体，宽度均为 240 dp、深蓝底色相同、无缝相接；拖动一起移动。控制栏高 48 dp，设置区高 160 dp，向上或向下平滑展开；开合时底部控制条的位置和大小保持不变。设置不启动新页面、不遮暗整个游戏。同组租户相同，每台客户端 ID 不同，复制模拟器后必须修改。服务器地址在打包时内置，旧的地址设置不再生效。保存后保持未启动；修改 ID 会暂停识别并断开旧连接，悬浮栏保持运行。然后在发牌前切到横屏游戏，点“启动”。首次连接尚无服务器版本时，不补传此前识别的旧手牌，需要重新观察可靠开局。
4. 结果面板固定左上角，不能拖动；控制栏可拖动。面板开局及摆牌时显示，确认提交后进入比牌时隐藏，结束隐藏。等待服务器时是空网格，收到有效结果后必须恰好显示 13 张。
5. 返回大厅不停止脚本。玩家正常进入下一桌后，脚本继续识别新局。退出或通知中的停止会释放采集和悬浮窗。

内置素材包包含 52 种手牌模板和 5 个状态模板；手牌阈值 0.80，状态阈值 0.9；常规采样目标 200ms，已看到开局且尚需完整手牌时短暂提高到 80ms。第一帧完整手牌也参与连续确认，两帧相同即可提交；收到服务器结果后立即刷新面板。白/黄底统一预处理已同时应用于模板和手牌截图，不处理状态按钮。数字与小花色独立核对，防止数字高分掩盖花色错误，规范见 [点数花色验证](docs/hand-corner-matching-v1.md)。

业务使用服务端 WebSocket `protocol_version=1`，7 台各上传一份完整手牌后返回剩余 13 张。截图只在本机处理，不上传图片。局中 9 张或 0 张不覆盖已提交手牌，按钮持续存在也不会重复开局。

## 构建和验证

JDK 17、Android SDK 35 / build-tools 35.0.0，Gradle 8.11.1、AGP 8.9.2、OpenCV 4.12.0。

```sh
./scripts/build.sh
./scripts/device-tests.sh 127.0.0.1:16384
```

正式交付默认内置 `http://139.199.12.90:8080`。需要改服务器时由打包人员传入 Gradle 参数 `-PjpqServerUrl=https://你的服务器`；运行时无地址输入框或偏好覆盖。

设备测试会安装内置本地地址 `http://127.0.0.1:18081` 的专用测试 APK，使用相邻 `JiPaiQi-Serve` 的临时数据库及 adb reverse；不写线上租户。需要模拟器允许悬浮窗。`JPQ_SERVER_CHECKOUT` 可指定服务端目录。测试完成后应重新运行 `scripts/build.sh` 并覆盖安装正式地址的 APK，不交付测试地址的构建产物。

Android 14/15 真机后台、省电策略及其他游戏皮肤尚未实测；200ms 是采样目标，识别超时会跳过旧帧，不堆积任务。13 张检查约束格式和数量，不能代替牌面识别准确性验证。
