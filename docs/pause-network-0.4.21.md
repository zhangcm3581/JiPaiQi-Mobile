# 暂停即停止网络 · 0.4.21

## 行为

- 刚打开应用、未点启动：不建立服务器连接，不识别、不上报。
- 保存不同租户/客户端ID：关闭原连接，保持暂停；点击启动才使用新ID连接。保存相同ID保持原运行状态。
- 暂停：关闭业务发送开关、取消WebSocket、停止心跳/上传重试/自动重连，隐藏清空结果面板。后台在感知连接断开后显示离线。
- 启动：重新建立连接，取得当前轮次，按持久记录与新画面恢复；不直接补传暂停前的未确认手牌。已在服务器接受的当前局等待真实结束，再从可靠新开局继续。
- 暂停前已发出的数据不能撤回，服务端已收到的手牌不会因暂停而删除。

保持0.4.20的完整13张两帧确认、手牌0.80/状态0.90、单次hand.submit和固定面板布局。此次只需更新客户端，已配套0.4.20的服务端无需再次更新。

## 实现与验证依据

原行为的原因是CaptureService.toggle仅关闭automatic识别标志，RoundSocket的连接与定时器继续工作。现在连接创建也受启动开关控制；暂停取消旧连接，发送、消息回调、心跳和重连入口检查允许工作标志。恢复时重建RoundSession并复用现有安全恢复机制，避免将旧牌重新标成当前轮。

真实模拟器测试先在旧代码复现：`floatingEntryAndIdentitySaveKeepServiceAlive` 因“未点击启动不允许连接”断言失败；修改后该测试通过。

专项覆盖：未启动离线、启动上线、修改ID暂停、暂停不重连；真实截图识别后暂停停止采样、面板隐藏、服务器换轮、启动后旧画面不上传、下次新局正常上传；MockWebServer接受一份未确认手牌后关闭发送开关，跨越3秒重试周期，确认不再发送、不重新握手。

原始测试记录保存在仓库 `docs/verification/pause-2026-09-11/`。本次测试连接本地隔离服务端，不修改线上租户。

验证结果：57项JVM测试及23项模拟器测试全部通过，共80项。本机已覆盖安装正式地址0.4.21并保持停止；测试前应用数据逐文件恢复核验一致。
