# 十三水客户端实现 · 0.4.12

2026-09-09。此文为当前行为的权威说明，覆盖旧版 HTTP 草案及历史审核中的旧规则。业务路径为 `CaptureService → Vision → RoundSession → RoundSocket`；协议保持 `protocol_version=1`，无需因面板显隐修改服务端协议。

## 本机识别和显示

- 目标采样 200ms，串行工作线程处理最新截图，不积压历史帧。空的图像到达回调不会丢弃已缓存的新截图；无新截图不重复确认。黑屏、遮挡、转屏、停屏、暂停或超过 1.5 秒无新截图打断视觉证据并隐藏面板。
- 一键配牌及固定“两对”灰/绿按钮共同作为摆牌界面信号，任一命中即可，避免鼠标遮挡一键配。连续两帧出现就显示左上角固定面板，不依赖手牌数量、网络握手或服务器结果。13 张、部分牌移到上方、全部摆好等待“确定”均显示。
- 有效画面中按钮持续消失 600ms 才隐藏，小于此保护时间的短暂漏识别不触发隐藏；素材1.2.0额外使用牌型按钮解决较长的鼠标遮挡。此时只是离开摆牌阶段，不发 `round.end`，不解除本局绑定。
- “继续”或“返回大厅”任一连续两帧命中，隐藏并清空面板；本局结束只生成一次请求。返回大厅后采集、连接与启动状态保持，玩家进入下一桌后自动识别下一局。
- 同局重新摆牌两帧确认后恢复面板；不会重复加入或上传。手动点击隐藏后，同阶段刷新不强行打开，新摆牌阶段可恢复。
- 面板固定物理像素 `(2,2)`，不能拖动，不自动换位置；控制栏仍可拖动。固定区域若与自定义识别区冲突，保持隐藏保护。
- 显示条件与数据有效性分开：服务器换轮、关闭轮次或停用租户时清空旧牌；本机仍摆牌则保留空等待/状态面板。迟到服务器结果不能打开已经隐藏的面板。
- 面板只接受本租户、当前已绑定且未结束/失效版本的服务器结果；必须恰好 13 张，每种身份最多两张。等待网格可以为空，不填本地识别牌或补齐假牌。

## 轮次、上传和网络恢复

1. 初次获得服务器快照后，观察有效无开局/结束状态至少 600ms，再连续两帧开局，生成一次 `round.join`。没有观察局间的半局启动只显示等待，不加入。初次快照之前没有版本依据的开局不能在后来补绑。
2. 视觉开局确定时固定目标版本：初次采用当时已知版本，后续采用上一目标版本加一。断网时继续采集可以保留这个版本及证据，重连后不能将旧手牌改到最新版本。
3. 连续两次相同的完整合法 13 张才冻结手牌，按点数/花色多重集比较、保留重复牌。`round.join` 绑定 ack 前不发送；每局只生成一份 `hand.submit`。已上传后仅识别状态，局中 9 张/0 张不会覆盖。
4. 本机真实结束→有效局间至少 600ms→下一次开局后才能加入下一轮。服务器推进本身不是本机结束证据。
5. 下一局已经出现但上一局 join/end ack 或新版本快照尚未到达时，显示空等待面板并保留已确认的新手牌，等待原请求确认后继续。若截图中断或又结束，放弃该等待证据。实际版本跳跃则停止业务同步，不猜版本。
6. 另一台先结束导致旧 `hand.submit` / `round.end` 收到 `ROUND_CLOSED` 时，丢弃已绑定旧轮请求，清空旧结果；等本机真实结束和下次开局继续。未成功绑定的拒绝不能当作成功。
7. 请求发送前持久保存；每 3 秒重试完全相同的请求 ID 和 JSON。每 15 秒协议 ping，连续 45 秒无任何服务器消息判定连接失效，断线后约 2 秒重连。响应期限在识别工作线程调度，另有实际处理耗时。
8. 租户不存在、停用、设备登记已满时显示具体错误并停止重复连接。旧连接被相同客户端 ID 替换（4001）显示 ID 冲突并停止争抢。用户修改 ID 并保存后直接替换连接，再点击启动恢复识别。
9. 进程重启丢失连续视觉证据，若曾加入/有未确认业务则停止业务上传。后台移除设备登记，重新连接收到 `bound_round_version=null` 后清除旧同步状态，并重新观察局间→开局；不得换身份/版本绕过。

## 配置与素材

服务端 `http://139.199.12.90:8080` 由 `BuildConfig.SERVER_URL` 内置，构建参数 `jpqServerUrl` 可指定其他部署；不读取旧 `endpoint` 偏好。租户 ID 与客户端 ID 由用户在悬浮栏设置填写，复制模拟器后客户端 ID 必须不同。上传默认允许，旧 `enabled=false` 被忽略，保存时移除旧开关和地址字段。

没有主面板。打开应用仅处理系统授权，成功后关闭透明入口并显示默认展开的悬浮栏；首次 ID 为空也能打开控制栏，点击启动会引导填写 ID。保存更改后在同一个工作线程关闭旧连接、清除旧手牌及会话引用、连接新身份；暂停识别但保留同一个采集服务和控制窗。相同 ID 保存不重连、不停止识别；取消不修改设置。设置弹窗中断视觉连续确认并隐藏结果窗口，保留控制栏，关闭后按原有阶段规则恢复面板。新连接仍需真实局间与完整 13 张确认。

内置包 1.1.0：参考 840×474，实际 1600×900 适配；52 手牌+3 状态模板；手牌彩色 0.85，状态彩色 0.9；继续搜索 `[0,380,840,94]`，返回大厅 `[270,382,153,76]`。

必须实现 `cards.background.yellow_to_white.v1`：手牌模板及截图 ROI 都执行 `B=max(B,min(G,R))`，随后才进行 color/gray/otsu 与匹配，状态图片不处理。未知必需能力或参数缺失的包拒绝导入。详见 [预处理说明](hand-background-preprocess.md)。

## 验证和限制

联调用本地真实 JiPaiQi-Serve 与独立数据库，不写生产租户；7 个 Android WebSocket 实例连续两局，返回结果与实际面板 104 个格子逐一核对。真实 MediaProjection 重放用户视频帧，验证开局→部分摆牌→等待确认→比牌→总局结束→下一桌，服务保持运行。完整结果见 [整体流程审核](full-flow-review-0.4.7.md)。

200ms 为调度目标，两帧显示确认通常约 200–400ms，稳定消失约 600–800ms，另加识别/绘制开销，不保证零延迟。当前设备为 MuMu Android 12L/API32；Android14/15真机、省电后台及其他皮肤未实测。

0.4.9：常用设置由服务直接打开 `TYPE_APPLICATION_OVERLAY` 小窗口（264×173 dp），不再启动 Activity。窗口贴近控制栏，不加全屏遮罩；初始不弹键盘，点输入框才编辑，横屏禁用全屏输入模式。120ms 淡入、100ms 淡出，只改变浮窗内容透明度。控制栏统一为 240×48 dp；结果网格大小及固定位置不变。

0.4.10：设置区改为与控制栏共用同一个原生悬浮窗口。统一 240 dp 宽度、深蓝背景与外侧圆角，没有中间间隙；控制栏 48 dp + 设置 160 dp。200ms 展开、160ms 收回，内容裁剪与位移配合淡入淡出；向上空间不足则向下展开。拖动整体移动，旋转保留尚未保存的输入；取消、返回、再点设置、收起均清理设置与输入焦点。身份、识别和网络协议不变。

0.4.11：设置的显示/隐藏保持底部控制条的原生窗口坐标和高度不变，避免触发 Android 的窗口位移动画。设置在紧贴控制条的独立输入窗口中展开，共用背景和圆角绘制，视觉仍为同宽、同色、无缝连接的整体。窗口位置只在用户拖动或屏幕旋转时同步调整。录制真实合成帧并跟踪控制条像素位置，防止“结束位置正确、过程中抖动”的回归。


## 0.4.12 联调审核补充
