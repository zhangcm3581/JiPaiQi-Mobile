# 0.4.17 覆盖安装／重启上报恢复修复

原因：旧 RoundSession 从持久记录恢复后设置 blocked，但正常结束和下一次开局不能解除；会在线却不上报，needsHands 也返回 false。

修复：仅对进程恢复设置 recovering。服务器确认绑定后，已持久确认结束且服务端恰好进入下一轮的会话，重新采集发牌前→开局证据即可恢复；中途重启必须连续确认两帧结束画面，然后从下一次开局恢复。同一服务端轮次尚未关闭时，用新采集的结束证据报告 round.end。旧 pending、旧手牌、结果全部丢弃，保留租户 ID 和客户端 ID。仍要求两个新鲜一致的完整 13 张手牌观测，join 确认后才提交。

限制：不把跨越多轮的旧绑定强行改成当前轮；服务端与绑定相差超过一轮仍需局间重新登记。存储失败和注册错误不会被结束画面解除。重启时正处于摆牌阶段且缺少结束证据，会跳过这一局，在结束后下一局恢复。

验证：
- 单元测试 57 项通过，0 失败；新增恢复测试在修改前 4 项失败，修改后通过。
- 真实本机 WebSocket + 已提交的服务端 HEAD（8b02679）：旧版状态机在独立 JVM 完成七端第 7 轮并保存记录，退出；新版在新 JVM 读取原文件，七端完成第 8 轮，逐格校验返回的全部 13 张。确认中途开局不重发旧请求、比牌隐藏面板、结束正常推进。
- 使用旧版持久化数据和生产状态机，没有使用模拟 ack。截图采集、Android 覆盖安装后实际运行本次未验证：本机模拟器未启动，ADB 连接被拒绝。没有触碰线上测试设备或生产数据。
- APK 包名 com.jpq.mobile，版本 0.4.17，versionCode 24，ARM64；与桌面 jpq.apk 签名一致；内置生产地址 http://139.199.12.90:8080，不含测试地址。
- 此恢复修复不需要服务端升级；客户端登记数量限制是另一个服务端修复，目前仍待发布。

使用：直接覆盖安装 0.4.17，重新打开、点击启动并允许屏幕录制。ID 保留。让脚本看到一次结束画面，再继续下一局；不要在当前摆牌中等待它补传旧局。
