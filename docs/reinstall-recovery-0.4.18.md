# 0.4.18 SYNC_REQUIRED 修复

现场截图明确显示：SYNC_REQUIRED：已有绑定记录，须确认结束到新局的切换。服务端第 8 轮，01–07 仍绑定第 7 轮。0.4.17 仅处理有本地历史的进程恢复，没有处理本地空记录与服务端旧绑定共存，或当前进程已收到 SYNC_REQUIRED 的情况。

修复：服务端快照显示已有绑定时，空本地会话进入恢复流程，不能发送 initial_start；当前请求收到 SYNC_REQUIRED 后进入可恢复状态。两帧结束证据后允许直接进入下一局，不再强制中间 600ms 空白。仍读取服务端绑定，不靠清空服务端记录恢复；旧手牌与旧请求不重放，开局确认后仍须两个一致的新鲜完整 13 张观测并获得 join ack 才上报。

验证：60 项 JVM 单元测试通过。新增 3 项在修复前失败，修复后通过，覆盖空历史、当前进程 SYNC_REQUIRED 恢复、12/14 张不得上传。隔离真实服务端与 Java WebSocket：旧会话七端第 7 轮成功；新进程七端分别在“无本地记录”和“恢复旧记录”两种场景下，均成功得到第 8 轮结果，每张牌逐格核对共 13 张，确认比牌隐藏面板。测试使用生产 RoundSession 源码和实际网络，未运行 Android 截图采集：当前没有 ADB 设备，不能据此宣称现场已恢复。

交付：0.4.18 / versionCode 25 / ARM64，生产服务器地址；带版本 APK 和桌面 jpq.apk 均已更新为本版。覆盖安装后打开、启动并授权录屏，经过结束→下一次开局。已跨度超过一轮的不同步记录仍不会强行跳轮，需局间重新登记；现场当前 8/7 属于本版已验证的恢复范围。此次无需额外更新服务端。
