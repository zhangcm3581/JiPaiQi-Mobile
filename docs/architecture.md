# 识别与记牌契约

运行配置只读取导出包的 manifest.json。内置 ZIP 是原始导出物的副本，不修改桌面工程或配置包。

流程：屏幕截图 → 等比映射 → 各区域模板匹配 → 牌行归属 → 连续确认 → 结算观察期 → 账本原子扣牌 → 悬浮条。

账本初始等待新局候选连续两次命中，提醒用户在发牌前开启。任何结束检测器命中优先锁定，同帧到期的候选也转入待核对。结束后开局原始特征必须先消失至少 restart_clear_ms，再无结束命中地连续 restart_confirm_samples 次出现才建立下一局。持续出现的弱颜色新局特征不会局内重置。

稳定显示与出牌事件分开。同一持续牌组只有一个事件 ID；画面消失不会撤销已计入。再次出现相同牌组若无可靠回合证据，留待核对而不自动重复扣除。候选成熟后先检查整个牌组是否超出实际牌库和该座位初始手牌，再一次性扣除。手动确认同样受这些约束；跨局记录不能扣入当前局。

截图由独立 HandlerThread 按配置时间采样。静止画面可能没有新的 ImageReader 缓冲，不能依赖图像回调推进保护计时；在屏幕仍可采集时保留最后一次观察推进时序，新缓冲优先。暂停、旋转、遮挡、比例错误、锁屏与停止采集清除缓存，禁止旧画面继续入账。

每次采集必须由 Activity 发起系统授权，随后启动 mediaProjection 类型前台服务。VirtualDisplay 每个授权会话只创建一次，旋转时修改显示尺寸及 Surface。停止回调释放 Surface、ImageReader、OpenCV Mat、悬浮窗和工作线程。

默认校准范围为全屏；宽高比偏差超过 3.5% 时拒绝直接拉伸。小幅比例差异采用中心等比有效画面。未知必需算法、缺失区域、损坏图片、不合理牌库和不安全 ZIP 路径拒绝导入。

图像到达回调仅保留最新 Image；采样 tick 处理并释放，防止堆积历史帧。悬浮条角落每 500ms 更新运行指示点，兼容 MuMu 静止画面合成刷新；点位位于悬浮条内部，遮挡检查仍覆盖整个悬浮条。
