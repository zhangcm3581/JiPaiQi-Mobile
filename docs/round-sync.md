# 轮次同步与面板时序 · 0.4.7

2026-09-09。本文件覆盖此前的待实现记录；完整实现与恢复边界见 [client-v2-implementation.md](client-v2-implementation.md)。

## 协议不变

使用 `protocol_version=1`：`round.state → round.join ack → hand.submit ack → round.result`。`start_event_id`、`sync_basis`、`previous_round_version`、`request_id` 和 `round_version` 已能表达一次视觉开局及重试。不增加面板显隐消息，由本机画面控制。

初次入局必须在获得服务器版本后观察有效局间至少600ms及连续两次开局。之后每轮要求本机真实结束→局间→下一次开局，固定目标为上一目标版本加一；不能将已有手牌跟随服务器版本变化重新上传。断续无按钮帧不能累计600ms，黑屏、暂停或截图错误不算局间证据。

上一轮 join/end ack、服务器下一版本晚到时保留已确认的等待开局，先完成原请求确认链，再绑定下一版本；完全未知版本的旧开局不得补绑，实际跨过版本也停止同步。

## 本机阶段

| 游戏画面 | 结果面板 | 协议动作 |
| --- | --- | --- |
| 开局，一键配连续两帧 | 显示空等待网格 | 有可靠入局证据才 join；稳定13张且绑定成功才 submit |
| 摆牌中：底部13张/9张/0张，按钮仍在 | 保持显示 | 不重复 join/submit |
| 全部摆好、尚未确定，按钮仍在 | 保持显示 | 不结束 |
| 确定后，按钮持续消失600ms，等待别人/比牌 | 隐藏 | 不发 end，不解除本局锁定 |
| 同局重新摆牌，按钮连续两帧恢复 | 恢复仍有效的本轮面板 | 不重复上传 |
| 继续或返回大厅任一连续两帧命中 | 隐藏并清空 | 本局一次 end |
| 大厅/局间 | 隐藏，脚本继续 | 等玩家进入下一桌及可靠新开局 |
| 服务器提前换轮/关闭，自己还在摆牌 | 显示空的等待/状态面板，旧牌清空 | 不把旧牌改成新版本 |
| 隐藏时迟到服务器结果 | 继续隐藏 | 仅接受仍有效的本轮结果 |
| 暂停、采集异常、转屏或超过1.5秒无新帧 | 隐藏、打断视觉证据 | 不伪造结束或开局 |

面板固定左上角 `(2,2)`，不拖动、不自动移动；点击可隐藏，同阶段的结果刷新不强行打开。结果数据必须来自服务器且恰好13张，等待网格为空不算不完整结果。

- 手牌：0.85，白黄底预处理同时应用于模板及 ROI；详见 [hand-background-preprocess.md](hand-background-preprocess.md)。
- 状态图：彩色0.9，开局主要使用“一键配”，另以固定位置的“两对”灰/绿按钮任一命中补充摆牌状态，避免鼠标遮挡一键配时面板闪烁；所有状态图仍为彩色0.9，颜色特征可不配置。
- 结束多个任一命中；继续搜索原840×474画面的 `[0,380,840,94]`，可覆盖中间及右移按钮；返回大厅 `[270,382,153,76]`。
- 采样目标200ms，开局/结束连续2次，离开摆牌与局间确认600ms。实际延迟包含采样、匹配和绘制。

验收涵盖持续摆牌不重发、摆完等待确定仍显示、比牌隐藏、迟到结果不弹出、其他设备先结束、延迟 ack、断线同版本恢复与旧牌拒绝改版本、返回大厅后同一服务继续下一桌。见 [审核记录](full-flow-review-0.4.7.md)。


## 2026-09-10 连续确认补充

即使结束特征仅命中一帧、尚不足以结束本局，也必须中断尚未完成的手牌连续确认。有效13张→单帧结束候选→有效13张，不能被算作连续两帧；已经确认且等待网络确认的请求继续按原 request_id 重试。协议字段与版本不变。手牌还需执行 [数字/花色独立验证](hand-corner-matching-v1.md)。
