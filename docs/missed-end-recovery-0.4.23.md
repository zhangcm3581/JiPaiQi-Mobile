# 漏结束确认后的跨局恢复 · 0.4.23

修复范围：仅客户端跨局状态恢复。服务端未修改、未部署，模拟器未更新。

## 复现

执行 `bash scripts/verification/check_missed_end.sh`。脚本启动独立本地服务和独立 SQLite 数据库，不访问线上。

8个测试身份，每局仅7个上传。第一局正常；第二局替换一个身份，仍正常；该局结束时仅对另一个客户端丢弃结束画面，随后继续提供发牌前画面及新的完整手牌。

旧版 c6a8f0c（0.4.22）在第三局等待收齐超时，漏结束客户端提示“服务端已换轮，等待本机真实结束”。修复版4局均收到7份上传，7端结果均逐格核对为正确13张。

这是可复现的故障路径；没有现场日志，不能断言它就是租户100002客户端02当时的唯一原因。

## 修复条件

保留正常结束识别路径，增加备用路径，必须同时满足：

- 已有上一局完整手牌，服务器当前版本高于本机旧局。
- 连接有效、租户启用，客户端没有处于阻断或结束状态。
- 在服务器换轮后，连续观察至少600毫秒非开局、非结束画面；随后观察新的开局。
- 连续两次识别到相同的合法13张牌，且与上一局牌集合不同。

截图中断、断线、版本再次变化、结束候选画面都会清除备用恢复证据。已有待确认请求仍按原请求及原版本处理，不能改版本重发。新结果保持13张及身份、轮次校验。

相同旧牌不会借服务器换轮再次上报。若新局恰好与旧局13张完全相同且又漏掉结束识别，本路径会保守等待正常结束证据。该修复不处理所有可能的识别故障或网络故障。
