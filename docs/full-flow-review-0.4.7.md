## 实现审核（Standards）

独立审核发现并修复以下运行路径问题；基于实际逻辑和项目契约，不将代码风格偏好列为硬错误。

- 不连续的无开局帧累积到600ms，可能错误武装新局：正向按钮命中立即重置未完成的局间计时。
- WebSocket仅发ping，没有无响应期限：加入45秒响应监测及2秒重连，保持原请求重试。
- ImageReader回调尚未取得新帧就释放原缓存：先获取，非空才替换，避免排队空回调丢掉最新画面。
- 无reply_to的登记错误被吞掉：租户不存在/停用/设备满明确显示并停止重复连接；4001表示重复客户端ID并停止争抢。
- 修复复核发现的4001关闭竞态：先在worker中记录终止状态再取消连接，后续回调不能安排重连。

## 需求审核（Spec）

独立审核发现并修复：

- 面板依赖网络握手/服务器轮次，可能开局不显示或自己仍摆牌却消失：显隐由本机阶段控制，服务器失效只清除旧牌；未返回结果时显示空等待网格。
- 新局已出现、上一局end ack或下一版本快照稍晚便永久阻塞：保留固定目标的新开局和已确认13张，按原请求确认链继续。
- 另一台先结束导致旧hand收到ROUND_CLOSED后永久停止：清理已绑定旧轮的拒绝请求，仍需本机真实结束后进入下一局。
- 等待握手的初次开局可能随重连版本变化而改绑旧牌：识别时固定已知版本，重连到更高版本不复用；首次尚无服务器版本的视觉证据不补绑，需要获取快照后重新观察局间→开局。
- 上一局join已生效但ack丢失，本机又观察到结束和下一局：先重试原join确认绑定，再补结束确认，最后加入下一轮，不能提前因bound未确认而封锁。

两轴最终只读复核均未发现上述修复仍有确定遗漏。实现审核5项、需求审核5项均已处理；这不等于证明所有设备和网络场景无缺陷。

## 最终显隐

| 阶段 | 面板 |
| --- | --- |
| 开局，一键配连续两帧出现 | 显示，结果未到则空网格 |
| 部分摆牌、全部摆好等待确定 | 显示，不依赖底部还剩几张 |
| 确定后离开摆牌，按钮持续消失600ms | 隐藏 |
| 继续/返回大厅任一连续两帧 | 隐藏并清空，脚本继续下一桌 |
| 隐藏后收到服务器结果 | 保持隐藏 |
| 同局重新摆牌 | 两帧确认后恢复，不重复上传 |
| 服务器先换轮，本机还摆牌 | 保留空状态面板，不能显示旧牌 |

固定左上角、禁止拖动。显示/隐藏复用同一个窗口。短暂漏检小于600ms不闪烁；暂停/无效截图独立隐藏，不当作游戏结束。
